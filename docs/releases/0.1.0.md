# ADKL 0.1.0 — initial release draft

Historical draft for the initial packaging milestone, not evidence that 0.1.0 was
published. See [unreleased changes](unreleased.md) for newer capability, background
task and inspection work. Final release notes must be reconciled with the exact
tagged artifact before publication.

Initial SDK scope for local authoring, native ADK adoption and customer-owned
agent deployment bundles. The slim SDK and console ZIP are separate release artifacts.

- Create an independent agent project in the UI, prepare its locked environment,
  inspect and test its native runtime, and build a checked deployment bundle.
- Adopt shared skill selection, history slicing, staged output and state adapters
  incrementally; inspect an existing host factory without rewriting its callbacks.
- Keep console assets, project content, credentials and virtual environments outside the SDK.
- Compose existing constructor dictionaries with `RuntimeBindings.merge_into`;
  inspect declarations repeatedly before consuming a binding.
- Recover stale local conversations through a typed conflict and Clear action.
- Opt into explicit runtime content paths while retaining code, prompt and skill
  dependency tracking. Factory summaries distinguish unknown counts from zero,
  and inspection reports stale authoring mappings.

Supported verification baseline: Python 3.13, locked Google ADK/LiteLLM versions
recorded in uv.lock, Flutter 3.44.0; Linux CI and macOS local checks. Other Python
versions permitted by package metadata are not a tested compatibility guarantee.
SDK users resolve runtime extras separately; the shipped platform SBOM describes
the tested lock, not every possible downstream resolution.

This is a pre-1.0 API: minor releases may require migration; patches are intended
to preserve supported behavior. The development console is local and single-user.
Production authentication, durable services, agent evaluation and infrastructure
remain host responsibilities. Native bundle execution is tested; container image
execution and managed hosting are not certified by this SDK release.

No migration from an earlier published SDK is required. Existing local 0.1.0
wheels may differ: retain existing project locks and wheels; do not silently
replace vendored wheels with the same filename. Prepare a new project/environment
when adopting the published artifact and compare behavior before switching.
